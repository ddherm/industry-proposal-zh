# 从新范本更新这套 skill

当用户提供更多优质本子或图模板，并要求学习、蒸馏或更新技能时使用本流程。

## 先找本次新增的材料

读取用户指明的文件、章节和借鉴重点。材料来自 GitHub 时先获取该版本；来自本地目录时按实际路径读取。[范本目录](../templates/catalog.md)记录已吸收材料，原始文件位于 [待处理目录](../templates/inbox)。沿用技能当前版本和已有规则，先核对同名文件是否有新版本。

## 把观察变成写作决定

- 查看真实目录、正文段落、相邻图题和考核表。每个吸收的要点应能回到具体章节、图号或表号。用户指出的优点优先核对，也检查它与上下文的联系。
- 文字样本重点看业务问题如何落到研究内容、方法怎样解释取舍、任务怎样交接，以及长段落怎样承载技术信息。保留其工程文体和准确状态，结合已有规则判断适用范围。
- 图模板先看图中的对象和箭头代表什么。可编辑 PPT 在副本上改，并随 skill 保留源文件；场景图记录适用对象和作业条件；论文图核对原文、图号和署名许可，再写图前图后说明。
- 把适用于多种任务的决定补入主入口；只适合某种行业、文体或图结构的经验放进相应参考。若新材料与旧习惯不同，写清各自适用条件，按用户本次偏好调整。

## 更新文件与记录

通用写作规则修改 `SKILL.md`，语言和论证实例补入 `references/proposal-writing.md` 或新建有明确用途的参考文件；新增参考应从入口或相关说明链接到。配图说明更新相应图示参考，模板资产放进 `assets`。给新范本在目录里记录材料版本、复核位置、吸收文件和日期。

业务数字、已获成果及单位能力仍属于原项目。整理示例时保留它们的归属；新项目用本项目依据填写这些内容。

## 完成一次可复用的更新

检查技能元数据、相对链接、重复或冲突规则。更换图模板时，打开可编辑文件并检查导出结果。对于改变了实际写作行为的规则，选择相关的一小段需求试写，检查有没有丢掉原有信息、承诺状态或图文接口。

用户要求上传时，将相关指令、参考和资产一并提交本仓库，并核对远端文件。用户要求同步本机技能时，先比较本机版本，保留同期独立修改，将本次变更同步到个人技能目录。汇报修改内容及确实仍缺的材料。
